Furnace fork: feature portfolio

Ideas for the personal fork of the Furnace chiptune tracker, grounded in its code, upstream user requests, community demand, and the maintainer's own goal of composing and tuning instruments through Claude. Ideas 01-06 came from the first run. Ideas 07-13 come from a second run that researched what other Furnace users ask for. Ideas 14-17 come from comparing Furnace with other trackers. Ideas 18-21 connect Michael's Lumatone keyboard. Idea 22 came on 2026-10-18 from a report that models judge audio better with a waveform image.

01 · Load songs from JSONAdvance8/10
persona
Josh in every Claude editing session; batch exporters who generate songs from scripts.
evidence
JSON export landed July–Aug 2026 (src/engine/fileOps/json.cpp:32, serializers at :24-29). No loadJSON exists and the loader dispatch never checks for JSON.
why it won
It's the cheapest way for an outside tool to write a song. The alternative, writing binary .fur directly, is complex and compatibility-sensitive.
scope note
Unknown whether the export is complete enough to rebuild a song (systems, compat flags, sample data). That's the first thing to check.
02 · CLI parity with GUI exportAdvance8/10
persona
Batch exporters on every render; Claude on every render or inspect call.
evidence
CLI flags at src/main.cpp:634-667 have no JSON, .fur, S98 or DMF output. VGM export is hard-coded at :1071. -o is claimed twice (:637, :660). -info skips duration and loop data the engine already computes. Upstream #540 asks for better CLI error feedback.
why it won
Additive flags with little merge cost, wiring engine calls that already exist.

persona

evidence

evidence
The FFT pitch detector in src/gui/tuner.cpp:37-59 only runs on live output. FFTW is bundled.
why
Lets Claude check pitch, brightness and envelope of what it made. Its value depends on 03.
05 · Detect sample pitch automaticallyValidate6/10
evidence
doc/9-guides/tuning-samples.md:10-12 tells users to compute semitone offsets by hand or use a web calculator.
open gap
Unknown whether Josh works with recorded samples.
result
Merged as #12 (2026-10-18) as two Claude tools, detect_sample_pitch and tune_sample, with no GUI change. Within 2 cents on test tones; a real piano sample went from +14 to −1.6 cents once tuned. Open: fixed-rate chips (YM2610 ADPCM-A, MSM6295) ignore the rate, note-map pitch shifts aren't flagged, and BRR and ADPCM samples can't be read.
06 · Write new chip emulators with ClaudeValidate8/10
persona
Josh, added mid-run: "I'd also like to be able to write new chip emulators using Claude".
evidence
Adding Watara Supervision touched 16 files (commit 9d279cead): a sound core, a driver, and about ten small registrations. A Dummy System template exists (src/engine/platform/dummy.cpp, sysDef.cpp:2824). Klattsch (390137b35) shows Furnace accepts invented chips. New chips are upstream's largest request theme (#873).
why Claude fits
The work follows a fixed pattern, and most Furnace chips are ports of existing open-source cores. A written recipe plus a sound-comparison test makes it repeatable.
open gap
Which pilot chip; how to check accuracy without real hardware; and chip IDs. Each chip's one-byte ID is saved in .fur files. Upstream uses 0x80–0xe7 plus 0xf0, 0xf1, 0xf5, 0xfc and 0xfd, so fork chips need a reserved range (maybe 0xf6–0xfb), and their songs won't open in upstream Furnace.
07 · Color themes and Perfect PaletteAdvance7/10
persona
People who want a light mode or their own palette. A r/FurnaceTracker thread asked for exactly this, and Josh relayed it.
evidence
The settings already have a Color tab (allSettings.cpp ~2453-2500) with scheme import and export (settings.cpp ~286-320). There are 361 color keys in guiConst.cpp, stored as plain key=value text. Dark/Light and the two accent colors show by default; the full color list is behind Guru mode. A reply in the thread had to point to Ctrl+, and the Color tab, so the feature exists but is hard to find.
shape
Ship a few presets including a real light theme. Add a visible entry point. Check text and background pairs against 4.5:1 contrast. Make scheme files round-trip with Perfect Palette, which already checks WCAG AA/AAA and exports 26+ formats. A menu link to perfectpalette.io is a product call for Josh.
open gap
Basic mode already derives buttons, tabs and headers from the two accents (settings.cpp:823-850). Text and window colors still come from dark defaults, so the Light option alone may not be readable. That is the first thing to check, then a palette has to map onto the 361 keys. Only one thread asks for this. Brief: ideas/007-color-themes.md.
08 · More export formatsValidate6/10
persona
Musicians who want to ship songs to standalone players, demos and hardware.
evidence
#857 asks for NSF, HES, SNDH, KSS, GBS and SPC (8 upvotes, 12 comments). S98, SAP-R and ZSM export already exists in src/engine/export. Idea 02 puts these exporters on the CLI, so each new format is available there too.
open gap
Some of these formats embed a player routine that must be written per chip, which is why upstream expects ROM export to cover this in 0.7. Pick one pilot format first.
brief
Written 2026-10-18. NSF first, as a register log plus a small 6502 replayer (like SAP-R), so no per-chip music driver is needed. 23 demo songs fit NSF. GBS is the runner-up; SPC waits for upstream's SPC700 player. S98 is a separate export path, not a ROM exporter.

17 · MIDI clock in and live queueingValidate4/10
evidence
LSDj syncs to other gear, and OpenMPT starts and stops from MIDI and queues patterns live. The fork sends MIDI clock out (playback.cpp:2740-2750) but nothing receives it. This is the same request as upstream #918. Idea 10 covers MIDI input fixes, so do the two together.
open gap
Live pattern queueing in Furnace is unverified. Testing needs a real clock source.
brief
Written 2026-10-18. The MIDI library drops clock messages today (rtmidi.cpp:143), and the engine ignores system messages. Tempo follow by measuring and retuning. Live queueing doesn't exist yet, needs no clock, and can ship alone. Song position out may send its bytes in the wrong order; step 1 checks.
18 · Lumatone plug-in testAdvance8/10
persona
Michael plays the Lumatone in both 12-tone and microtonal tunings. He wants to record into patterns, play live, and have the keys light up with the song.
evidence
The fork has MIDI note input, a polyphonic option, and "direct channel", which sends MIDI channel N to tracker channel N (gui.h:1285, settings.cpp:208). MIDI controllers can type effect values (gui.cpp:5218-5260). The Lumatone's 12-ET preset puts its sections on separate MIDI channels.
shape
No code. Michael plugs in, tries the 12-ET preset with direct channel and poly input on and off, records a pattern, and plays live. Write down what works and what breaks. That list scopes 19-21.
brief
Written 2026-10-18: ideas/018-lumatone-plug-in-test.md, a 13-step checklist plus a results form. Writing it corrected four claims above. The 12-ET preset uses channels 1-6 inside every section, not one channel per section. There is no polyphonic setting; chords come from the Mono/Poly/Chord button. Direct channel changes which channel plays a note, not which one records it. Furnace sends no sysex today, so the "Light Show" output does nothing.
19 · Lumatone layout import and microtonal inputAdvance7/10
evidence
A Lumatone mapping (.ltn) stores each key's channel, note and color, and the manual says mappings are pitch-agnostic: the receiving instrument decides the pitch. The fork's pitch math is fixed 12-tone (engine.cpp:1840-1920), but every channel has an E5xx pitch effect.
shape
Load a .ltn file plus a tuning (an EDO size or a Scala file). For each key, work out the nearest 12-tone note and the detune. Recording writes the note plus an E5xx on that row. Live play applies the same detune to the note it previews. Each tracker channel plays one note at a time, so a per-channel detune fits. No engine change, and it works on every chip.
open gap
The range and step size of E5xx are unchecked, so it may be too coarse for large tunings such as 53-EDO. Chips with coarse frequency registers will be off whatever we do.
brief
Written 2026-10-18: ideas/019-lumatone-layout-microtonal-input.md. E5xx steps are 0.78 cents and reach ±50 cents, enough for any EDO, but only with linear pitch, and every note row needs one. Corrections to the shape above: live play needs a small engine change, because the engine drops the MIDI channel and a key release stops every channel on that note. A dedicated effect column is needed. A .ltn file holds no tuning, so the import needs a steps-per-channel setting. On SN76489 and NES, close 53-EDO notes merge in high octaves. Spike steps 1-4 need no one; 5-7 need Michael after 18.
20 · Lumatone key lights that follow the songValidate6/10
evidence
Every Lumatone key has a color LED, set by Lumatone Editor over MIDI. The editor's source is public under BSD-3 (TerpstraSysEx.2014), which fits Furnace's GPL, so the color commands can be learned from it. The fork's MIDI out already sends sysex (rtmidi.cpp:180) and stores a color per channel (gui.cpp:1091).
shape
During playback, light each key as its note plays, in its channel's color, then restore the layout colors. Channel colors can come from the theme in 07. The lit keyboard can appear in Michael's videos next to the scopes from 14.
open gap
I have not extracted the color command yet. A busy song may change lights faster than the keyboard accepts sysex, so measure the update rate first.
brief
Written 2026-10-18. The LED command is in the Lumatone Editor source: 14 bytes a key, one message at a time, with an answer from the keyboard. Busy songs need about 180 messages a second, fine over USB. Hook it in the GUI once per frame; no engine change. Furnace must never send the save-preset command.
21 · Microtonal tuning tablesValidate6/10
persona
Revived from the parked list (#881), now with a real user in Michael.
evidence
A song stores one tuning value, the A reference (song.h:312), limited to 400-500 Hz. Notes become frequencies through a fixed 12-tone formula (engine.cpp:1840-1920).
shape
A tuning table per song, as an EDO size or a Scala file, used wherever a note becomes a frequency. Optionally follow a live tuning source through ODDSound's MTS-ESP.
open gap
This changes pitch math for every chip and the .fur format, so these songs would play wrong in upstream Furnace. 19 is the cheap path to try first. Check the MTS-ESP library's license.
brief
Written 2026-10-18. A per-song offset table at four note<<7 spots retunes almost every chip. The hard part is note names and range: 53-EDO fits 3.4 octaves. The MTS-ESP client is 0BSD and fine for GPL. Upstream would load these songs in 12-tone without a warning. 21 does not help coarse chips more than 19 does.
22 · Show Claude the audioValidate7/10
persona
Josh and Claude in every composing session (idea 03).
evidence
The author of fframes reports that models judge audio "significantly better" with a waveform image than with a text summary. Our own 004 blind test got 1 of 3 on instrument edits from text alone. The mcp 2.x library can return images, and numpy and ffmpeg can draw them, so there are no new dependencies.
shape
An optional image on four tools, in order: render (a waveform per channel with order lines and a spectrum strip), preview_instrument (envelope, close-ups, harmonic bars), detect_sample_pitch (loop points and measured part), and an export_video contact sheet. The text reports stay.
open gap
Whether Claude Code passes the image through here, and whether it helps. A blind A/B test on six tasks with known answers decides. Images cost about 1-2k tokens each, so they stay opt-in. fframes itself is not used: its waveform command needs Rust and works only on fframes video projects. Brief: ideas/022-show-claude-the-audio.md.
result
Merged as #14 (2026-10-18), all four images. Blind test with fresh agents on eight questions: text plus image got 8 of 8, text alone 5 of 8 (two of them guesses). Images won on where things happen (which order clips, where a channel drops out), on a clicking loop, and on an instrument edit the text got wrong. The test also caught two drawing bugs: one-pixel clip marks were invisible, and idle chips were drawn as playing. Claude Code shows the images through the live server.

002 · CLI export parityHandoff planideas/002-cli-export-parity.md

Eight verified steps that add -furout, -jsonout, -s98out and VGM options, put duration and loop in -info, and fix the -o collision. Each step ends in a byte-identical check against the current build.

kickoff prompt
Read C:\dev\furnace\furnace\ideas\002-cli-export-parity.md in full before doing anything.
